# MedVerify — Prototype (Phase 0/1 MVP)

MedVerify is a Chrome extension and FastAPI backend that verifies medical claims generated by ChatGPT against evidence from PubMed using a biomedical Natural Language Inference (NLI) model.

This prototype corresponds to **Phase 0/1** of the project and focuses on:

- One LLM target: **ChatGPT (Web)**
- One evidence source: **PubMed**
- Three-category verdict:
  - ✅ Supported
  - ❌ Contradicted
  - ⚪ No Evidence

---

# Features

- Extracts medical claims from ChatGPT responses
- Retrieves supporting evidence from PubMed
- Caches retrieved evidence using ChromaDB
- Uses a biomedical NLI model for claim verification
- Displays trust scores and evidence directly inside ChatGPT
- Works completely locally after the initial model download

# Backend Setup

Clone the repository:

```bash
git clone <repository-url>
cd MedVerify
```

Create a virtual environment:

```bash
cd backend

python -m venv venv
```

Activate it:

### Windows

```bash
venv\Scripts\activate
```

### macOS/Linux

```bash
source venv/bin/activate
```

Install dependencies:

```bash
pip install -r requirements.txt
```

Download the required spaCy model:

```bash
python -m spacy download en_core_web_sm
```

Install the scispaCy medical model:

```bash
pip install https://s3-us-west-2.amazonaws.com/ai2-s2-scispacy/releases/v0.5.4/en_core_sci_sm-0.5.4.tar.gz
```

Start the backend:

```bash
uvicorn main:app --reload --port 8008
```

# First Run

On the first execution, the backend downloads the following Hugging Face models automatically:

- `pritamdeka/PubMedBERT-MNLI-MedNLI`
- `pritamdeka/PubMedBERT-mnli-snli-scinli-scitail-mednli-stsb`

No Hugging Face API key is required.

After downloading once, the models are cached locally.

# How It Works

For every ChatGPT response, MedVerify adds a:

> 🩺 **Verify with MedVerify**

button beneath the assistant message.

When clicked, the system:

1. Extracts medical claims.
2. Searches PubMed for relevant evidence.
3. Runs biomedical NLI verification.
4. Computes a trust score.
5. Displays:
   - Verdict
   - Trust Score
   - Supporting evidence
   - PMID links

# Technical Details

## Claim Extraction

- spaCy sentence segmentation
- scispaCy medical entity filtering (`en_core_sci_sm`)
- Falls back to `en_core_web_sm` if scispaCy is unavailable

---

## Evidence Storage

- Local ChromaDB vector database
- Prevents repeated PubMed queries
- Improves performance over time

---

## Biomedical NLI

Model:

```
pritamdeka/PubMedBERT-MNLI-MedNLI
```

The model is specifically fine-tuned for biomedical textual entailment and contradiction tasks.

---

## Trust Score

Current implementation:

```
Trust = 0.55E + 0.20R + 0.10A + 0.15Q
```

Where:

- **E** = Evidence relevance
- **R** = Retrieval confidence
- **A** = Cross-source agreement *(placeholder in Phase 0)*
- **Q** = Evidence quality *(placeholder in Phase 0)*

Since only PubMed is used in this prototype, **A** and **Q** are fixed placeholder values.
